# 合同/法务文档审查 Agent 场景分析

## 1. 场景目标

### 核心问题
传统合同审查依赖人工逐条审核，存在三大痛点：**耗时长**（一份50页合同需数小时）、**易遗漏**（人工疲劳导致关键条款未被审查）、**标准不统一**（不同审查人员判断标准差异大）。

### 目标用户
- **企业法务部门**：日常合同审查、供应商协议批量审核
- **律所律师**：尽职调查中的大量合同分析
- **合规部门**：监管合规性自动检查
- **采购/销售团队**：快速评估合同风险

### 核心价值
| 维度 | 传统方式 | Agent 辅助 |
|------|----------|-----------|
| 审查效率 | 数小时/份 | 分钟级 |
| 遗漏率 | 5%-15% | <2% |
| 标准化 | 依赖个人经验 | 统一审查标准 |
| 成本 | 高（外部律师费用） | 低（自动化处理） |

## 2. 审核对象

### 审查内容
- **条款提取**：识别价格、期限、违约责任、争议解决、保密条款等关键要素
- **风险识别**：标记不利于己方的条款（单方解除权、高额违约金、管辖地不利等）
- **合规检查**：验证是否符合《民法典》《劳动合同法》等相关法律法规
- **一致性校验**：比对合同文本与标准模板的差异
- **完整性检查**：确认必备条款是否缺失（如签章、生效条件、争议解决方式）

### 审核粒度
- **整体级**：合同整体风险评估和合规性判断
- **条款级**：逐条审查并给出风险评级（高/中/低）
- **词句级**：关键术语的准确性校验（如"定金"vs"订金"）

### 不同类型合同差异
| 合同类型 | 审查重点 | 技术难度 |
|----------|----------|----------|
| 劳动合同 | 劳动法合规、员工权益 | 中 |
| 采购合同 | 价格条款、交付标准、违约责任 | 中 |
| 租赁合同 | 产权归属、维修责任、续租条款 | 中 |
| 技术合作 | 知识产权归属、保密条款 | 高 |
| 跨境合同 | 适用法律、争议解决、外汇风险 | 高 |

## 3. 为什么需要 LangChain 做人机交互流程

### LLM 的不确定性
LLM 在合同审查中存在固有不确定性：
- 可能产生**幻觉**，错误解读法律条款含义
- 不同法域对同一术语定义不同，模型缺乏明确判断依据
- 合同上下文的理解需要领域专业知识和最新法规信息

### HITL 的必要性
法律审查结论具有**法律效力**，不能完全交由 AI 自主决策：
- 人工复核是风险兜底的最后防线
- 审核人员的反馈可以帮助 Agent 持续优化
- 法律责任归属需要明确的人工确认环节

### LangChain/LangGraph 的 HITL 能力
- **interrupt 机制**：在关键节点暂停执行，等待人类决策
- **三种决策类型**：approve（批准执行）、edit（修改参数后执行）、reject（拒绝并给出反馈）
- **状态持久化**：通过 checkpointer 保存中断状态，支持异步审核
- **流式响应**：审核人员可以实时查看 Agent 的审查进度

### 交互流程示例
```
用户上传合同 → Agent 解析文本 → 逐条审查 → 发现高风险条款
    ↓
触发 interrupt → 暂停 Agent → 推送审核请求给法务人员
    ↓
法务人员查看：风险条款原文 + Agent 判断依据 + 风险评级 + 法律依据
    ↓
决策：approve（确认风险）/ edit（调整风险等级）/ reject（认为误报）
    ↓
Agent 根据反馈继续 → 生成最终审查报告
```

## 4. 现有产品与技术实现

### 市面产品
| 产品 | 公司 | 核心技术 | 定位 |
|------|------|----------|------|
| Kira Systems | Litera | NLP + ML | 尽职调查合同分析 |
| Luminance | Luminance | 专有 ML 模型 | AI 法律科技平台 |
| Ironclad | Ironclad | AI + CLM | 合同全生命周期管理 |
| LegalSifter | Thomson Reuters | AI + 法律专家知识 | 合同审查工具 |
| 法大大 | 法大大 | NLP + 知识库 | 国内电子合同+审查 |

### 技术路线对比
- **传统 NLP + 规则引擎**：基于关键词和正则表达式，准确率高但覆盖范围有限
- **大模型 + Prompt**：利用 LLM 语义理解，覆盖广但误报率高
- **混合方案（RAG + HITL）**：结合知识库检索和人工审核，平衡准确率与覆盖率

### Agent 架构模式
- **单 Agent**：一个 LLM 完成所有审查任务，简单但容易遗漏
- **多 Agent 协作**：解析 Agent + 审查 Agent + 合规 Agent 分工
- **人机协同 Agent**：Agent 初审 + 人工复核 + Agent 生成报告（推荐方案）

## 5. 用户场景与使用流程

### 典型操作路径
1. **上传合同**：用户登录系统，上传 PDF/Word 格式合同
2. **选择审查模式**：风险审查 / 合规检查 / 条款比对 / 综合审查
3. **Agent 自动审查**：解析合同、提取条款、识别风险、检查合规
4. **人工审核**：高风险条款触发人工确认，审核人员审批/修正
5. **生成报告**：输出结构化审查报告（风险评级 + 修改建议 + 法律依据）
6. **后续处理**：下载报告或在线编辑合同
