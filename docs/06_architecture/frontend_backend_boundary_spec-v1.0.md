# 前后端功能边界规范 — ContractReview v1.0

> 本文档严格基于 `03_problem_modeling/problem_core.md` 和 `04_interaction_design/interaction_core_final.md` 收口而成，不做自主发散。
> 本文档定义前后端职责划分、数据流向和操作权限边界，作为后续 API 规范和实现计划的输入。

---

## 1. 职责划分总览

| 职责域 | 前端负责 | 后端负责 |
|--------|---------|---------|
| 用户界面 | 页面渲染、交互逻辑、状态管理 | — |
| 文件上传 | 文件选择、客户端校验、上传进度展示 | 文件接收、存储、格式校验 |
| 文档解析 | 解析进度展示、失败提示 | 文档解析、条款提取、文本清洗 |
| AI 审查 | 审查进度展示、阶段状态渲染 | LLM 调用、风险识别、合规检查 |
| 人工审核 | 审核界面、操作交互、状态反馈 | 审核决策持久化、状态流转 |
| 报告生成 | 报告在线预览、PDF 下载触发 | 报告数据聚合、PDF 文件生成 |
| 状态管理 | 页面状态、UI 状态、本地缓存 | 业务状态机、状态持久化、状态推送 |
| 操作日志 | 日志展示界面 | 日志记录、查询接口 |

---

## 2. 前端职责清单

### 2.1 前端必须发起的操作

| 操作 | 触发时机 | 说明 |
|------|---------|------|
| 上传文件 | 用户选择/拖拽文件后 | 发送 multipart/form-data 请求 |
| 取消上传 | 用户点击取消 | 中断上传请求 |
| 取消审查 | 用户确认取消 | 发送取消请求，删除审查记录 |
| 重试审查 | 用户点击重试 | 发送重试请求（从断点继续） |
| 重新上传 | 解析/审查失败后 | 发送新文件上传请求 |
| 审批操作（同意/编辑/驳回） | 用户点击操作按钮 | 发送审批决策请求 |
| 批量审批 | 用户批量操作 | 发送批量审批请求 |
| 生成报告 | 用户点击生成报告 | 发送报告生成请求 |
| 下载报告 | 用户点击下载 | 触发浏览器文件下载 |
| 查看操作日志 | 用户点击日志入口 | 发送日志查询请求 |

### 2.2 前端负责的数据展示

| 数据 | 来源 | 展示方式 |
|------|------|---------|
| 文件基本信息（名称、大小、上传时间） | 后端返回 | 文件信息栏 |
| 文档解析进度（阶段状态、百分比） | 后端推送（WebSocket/SSE） | 阶段进度面板 |
| AI 审查进度（4 阶段状态、总进度） | 后端推送（WebSocket/SSE） | 阶段进度面板 + 总进度条 |
| 审查失败原因和详情 | 后端返回 | 失败面板 |
| 风险项列表（等级、摘要、位置、置信度） | 后端返回 | 分组卡片列表 |
| 风险项详情（原文、审查意见、法律依据、建议） | 后端返回 | 左右分栏详情面板 |
| 总体风险评分和风险统计 | 后端返回 | 总览卡片 |
| 审批操作结果（确认/修正/驳回） | 后端返回 | 状态标签更新 + Toast |
| 操作日志（时间线） | 后端返回 | 日志面板 |
| 审查报告（执行摘要、风险清单、建议汇总） | 后端返回 | 报告预览页 |

### 2.3 前端负责的本地处理

| 处理项 | 说明 |
|--------|------|
| 文件格式校验 | 检查扩展名和 MIME Type（.docx / PDF） |
| 文件大小校验 | 检查 ≤ 50MB |
| 重复文件检测（客户端） | 比对文件名和大小，提示可能的重复 |
| 上传进度计算 | 根据上传字节数计算百分比 |
| 风险项筛选和排序 | 前端本地过滤（按等级、状态）和排序 |
| 批量选择管理 | 维护选中项列表 |
| 已处理项视觉弱化 | CSS 透明度调整、折叠展开 |
| 页面路由管理 | 根据审查状态控制页面跳转 |

## 3. 后端职责清单

### 3.2 后端负责的业务处理

| 处理项 | 说明 |
|--------|------|
| 文件接收与存储 | 保存上传文件到存储系统，返回文件 ID |
| 服务端格式校验 | 校验文件实际内容是否为有效 .docx 或 PDF |
| 文档解析 | 解析文档结构，识别条款边界，提取文本 |
| 条款提取 | 从解析后的文本中提取关键条款（价格、期限、违约责任等） |
| 风险识别 | 调用 LLM + 规则引擎识别风险条款并评级 |
| 合规检查 | 对照法规库验证合同合规性 |
| 审查状态管理 | 维护合同状态机（已上传→解析中→审查中→待审核→完成） |
| 审核决策持久化 | 保存用户的审批操作（同意/编辑/驳回）及变更内容 |
| 报告数据聚合 | 聚合审查结果生成结构化报告数据 |
| PDF 报告生成 | 根据报告数据生成 PDF 文件 |
| 操作日志记录 | 记录每次用户操作（操作人、时间、类型、变更内容） |
| 文档锁定 | 审查中锁定原文档，禁止修改 |

### 3.2 后端必须提供的数据接口

| 接口 | 数据内容 | 触发时机 |
|------|---------|---------|
| 上传文件 | 接收文件，返回 reviewId 和文件信息 | 用户上传文件 |
| 获取审查状态 | 返回当前审查状态和进度信息 | 前端轮询或页面加载 |
| 推送审查进度 | 实时推送解析/AI 审查阶段进度 | 审查过程中（WebSocket/SSE） |
| 获取风险项列表 | 返回所有风险项（等级、位置、摘要、置信度、处理状态） | AI 审查完成后 |
| 获取风险项详情 | 返回单个风险项的完整信息（原文、审查意见、法律依据、建议） | 用户展开风险项时 |
| 提交审批决策 | 接收用户的审批操作（同意/编辑/驳回），返回更新后的状态 | 用户操作后 |
| 提交批量审批 | 接收批量审批操作，返回更新后的状态 | 用户批量操作后 |
| 取消审查 | 接收取消请求，删除审查记录 | 用户取消 |
| 重试审查 | 接收重试请求，从断点继续审查 | 用户重试 |
| 生成报告 | 触发报告生成，返回报告数据 | 用户点击生成报告 |
| 下载报告 | 返回 PDF 文件流 | 用户点击下载 |
| 获取操作日志 | 返回操作日志列表（时间线） | 用户查看日志 |

### 3.3 后端负责的状态流转

```
已上传 → 解析中 → 解析完成 → AI 审查中 → 审查完成
    ↓        ↓                    ↓           ↓
  已取消  解析失败           审查失败    待人工审核
    ↓        ↓                    ↓           ↓
  重新上传  重新上传          重试/重传    人工审核中
                                              ↓
                                        报告可导出
```

后端负责：
- 维护上述状态机的合法流转
- 状态变更时通知前端（通过 WebSocket/SSE 推送或轮询）
- 状态持久化（数据库记录）
- 文档锁定（审查中状态禁止修改原文档）

## 4. 数据流向图

### 4.1 上传与审查流程

```
前端                        后端
 │                          │
 │──① 上传文件─────────────→│ 接收文件，存储，创建审查任务
 │                          │
 │←──② 返回 reviewId───────│  返回文件信息和 reviewId
 │                          │
 │                          │── 解析文档 ──→ 提取条款 ──→ 风险识别
 │←──③ 推送进度─────────────│  实时推送阶段进度（SSE/WS）
 │                          │
 │  前端展示进度条           │
 │                          │
 │←──④ 审查完成─────────────│  返回风险项列表
 │                          │
```

### 4.2 人工审核流程

```
前端                        后端
 │                          │
 │──⑤ 提交审批决策─────────→│  保存决策，更新风险项状态
 │  （同意/编辑/驳回）        │
 │←──⑥ 返回更新结果─────────│  返回更新后的风险项状态
 │                          │
 │  前端更新 UI 状态         │
 │                          │
 │  (循环 ⑤-⑥ 直到全部处理)  │
 │                          │
 │──⑦ 生成报告请求─────────→│  聚合数据，生成报告
 │←──⑧ 返回报告数据─────────│  返回结构化报告
 │                          │
```

## 5. 核心数据实体与职责

| 数据实体 | 前端负责 | 后端负责 |
|----------|---------|---------|
| Contract（合同） | 展示基本信息（名称、大小、时间） | 存储元数据、关联文档 |
| Document（文档） | 展示原文（高亮风险条款） | 存储原始文件、解析后文本 |
| Clause（条款） | 展示条款位置和摘要 | 条款提取、类型标注、边界识别 |
| RiskItem（风险项） | 展示风险等级、摘要、详情、操作 | 风险识别、评级、置信度计算 |
| ReviewDecision（审核决策） | 收集用户操作（同意/编辑/驳回） | 持久化决策记录、更新风险项状态 |
| ReviewReport（审查报告） | 在线预览、PDF 下载 | 报告数据聚合、PDF 生成 |
| AuditLog（操作日志） | 时间线展示 | 记录操作、提供查询 |

## 6. 前后端交互协议

### 6.1 通信方式

| 场景 | 通信方式 | 说明 |
|------|---------|------|
| 文件上传 | HTTP POST (multipart/form-data) | 大文件上传 |
| 普通请求/响应 | HTTP RESTful API | 获取状态、提交决策、生成报告 |
| 实时进度推送 | Server-Sent Events (SSE) 或 WebSocket | 解析进度、AI 审查进度 |
| 报告下载 | HTTP GET (stream) | PDF 文件流 |

### 6.2 状态同步策略

| 策略 | 说明 |
|------|------|
| 前端轮询 | 作为 SSE/WS 的降级方案，每 3 秒轮询审查状态 |
| 后端推送 | 首选方案，通过 SSE 实时推送进度更新 |
| 页面返回刷新 | 用户从后台返回页面时，自动请求最新状态 |
| 多端同步 | 后端推送状态变更，所有打开该页面的前端实例同步更新 |

## 7. 边界约束

### 前端不应做的事情
- 不执行文档解析（解析逻辑在后端）
- 不调用 LLM 进行风险识别（AI 推理在后端）
- 不直接操作数据库状态（通过 API 触发状态流转）
- 不生成 PDF 报告（报告生成在后端）

### 后端不应做的事情
- 不做客户端文件格式预校验（前端已做，后端只做最终校验）
- 不控制前端页面跳转和 UI 展示逻辑
- 不直接推送 UI 组件渲染指令（只推送数据，前端决定如何展示）
