# 交互链路设计总结

> 本阶段由 Agent Team 协作完成：
> - **upload-designer**：上传与解析交互链路设计
> - **state-designer**：Agent 审核中状态处理设计
> - **approval-designer**：人工审批交互设计
> - **Lead**：汇总分析

---

## 1. 完整交互链路总览

```
用户点击上传
    ↓
┌─────────────┐     失败 → 格式提示 + 重新选择
│  文件校验    │
└──────┬──────┘
       ↓ 通过
┌─────────────┐     失败 → 原因提示 + 重试
│  文件上传    │  ← 进度条实时反馈
└──────┬───────┘
       ↓ 成功
┌─────────────┐     失败 → 分类原因 + 重新上传
│  文档解析    │  ← 阶段轮播提示 + 进度条
└──────┬───────┘
       ↓ 成功
┌─────────────┐     失败 → 断点续审 + 最多3次重试
│ AI 审查中    │  ← 4阶段进度 + 后台运行
│ ①结构解析    │
│ ②条款提取    │
│ ③风险识别    │
│ ④合规检查    │
└──────┬───────┘
       ↓ 完成
┌─────────────┐
│ 风险项列表    │  ← 按高/中/低分组展示
└──────┬───────┘
       ↓ 有高风险项
┌─────────────┐
│ 人工审核     │  ← 同意/编辑/驳回 三种操作
│ (HITL)      │  ← 左右分栏原文对照
└──────┬───────┘
       ↓ 全部处理完成
┌─────────────┐
│ 生成报告     │  ← PDF 导出 + 在线预览
└─────────────┘
```

## 2. 关键交互设计决策

### 2.1 上传环节
| 决策 | 选择 | 原因 |
|------|------|------|
| 上传方式 | 单文件 + 拖拽 | MVP 范围，批量上传二期 |
| 格式支持 | Word (.docx) + PDF 文本型 | 覆盖 90%+ 使用场景 |
| 大小限制 | 50MB | 平衡服务器负载和用户需求 |
| 重复检测 | 7 天窗口 | 避免重复审查浪费资源 |

### 2.2 审核状态
| 决策 | 选择 | 原因 |
|------|------|------|
| 进度展示 | 4 阶段拆解 + 总进度条 | 让用户感知 AI 正在工作 |
| 后台运行 | 支持 | 审核耗时可能超过 2 分钟 |
| 失败重试 | 断点续审，最多 3 次 | 已完成的阶段不重复执行 |
| 文档锁定 | 审核中不可修改 | 保证审查一致性 |

### 2.3 人工审核
| 决策 | 选择 | 原因 |
|------|------|------|
| 列表布局 | 卡片式 + 按风险等级分组 | 视觉区分度高，符合竞品主流设计 |
| 原文定位 | 左右分栏 + 高亮 | 审核体验最佳，直观对照 |
| 操作方式 | 同意/编辑/驳回 | 对齐 LangChain HITL 的 approve/edit/reject |
| 批量操作 | 批量确认 + 批量驳回 | 提升审核效率，处理低置信度项 |

## 3. 全局状态机

```
已上传 → 解析中 → 解析完成 → AI 审查中 → 审查完成
    ↓        ↓                    ↓           ↓
  已取消  解析失败           审查失败    待人工审核
    ↓        ↓                    ↓           ↓
  重新上传  重新上传          重试/重传    人工审核中
                                              ↓
                                        报告可导出
```
