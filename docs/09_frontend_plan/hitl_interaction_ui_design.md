## 1. 审批操作 UI（Approve / Edit / Reject）

每条风险项卡片底部固定显示三个操作按钮：

```
[ 确认 ]  [ 修改 ]  [ 驳回 ]
```

按钮默认禁用条件：当 `human_review_status != "pending"` 时，三个按钮全部隐藏，替换为已处理状态标签。

---

### 1.1 Approve（确认）

#### 触发条件

| 置信度 | 确认方式 | 理由 |
|--------|----------|------|
| >= 70% | **内联直接确认** | AI 高置信度，用户信任成本低 |
| < 70%  | **弹出确认对话框** | 低置信度需要用户二次确认，防止误操作 |

#### 1.1.1 高置信度确认（内联模式）

**正常态**：

```
+------------------------------------------------------------------+
|  [HIGH] 风险 #001 - 违约责任                                       |
|  置信度: 92%  ||||||||||||||||||||█░                              |
|  ...（风险项卡片内容）...                                           |
|  +--------------------------------------------------------------+|
|  |  [ 确认 ]   [ 修改 ]   [ 驳回 ]                                ||
|  +--------------------------------------------------------------+|
+------------------------------------------------------------------+
```

**交互态（点击确认后 300ms 动画期）**：

```
+------------------------------------------------------------------+
|  [HIGH] 风险 #001 - 违约责任                                       |
|  置信度: 92%  ||||||||||||||||||||█░                              |
|  ...（风险项卡片内容）...                                           |
|  +--------------------------------------------------------------+|
|  |  [ 确认 ]   [ 修改 ]   [ 驳回 ]                                ||
|  +--------------------------------------------------------------+|
|                                                                  |
|  [动画: 确认按钮变为绿色勾选图标，向右上角飞出消失]                      |
+------------------------------------------------------------------+
```

**完成态（卡片折叠 + 视觉弱化）**：

```
+------------------------------------------------------------------+
|  [HIGH] 风险 #001 - 违约责任                        [已确认] [展开v]|
|  置信度: 92%  操作人: user-001  2026-04-10 07:00                   |
|  透明度: 60% | 默认折叠 | 点击展开可查看完整内容                       |
+------------------------------------------------------------------+
```

- 状态标签 `已确认`：绿色背景 `#E8F5E9`，绿色文字 `#2E7D32`
- Toast 提示：右上角 `已确认`（绿色背景，1.5s 自动消失）

#### 1.1.2 低置信度确认（对话框模式）

当 `confidence < 70%` 时，点击"确认"弹出对话框：

```
+--------------------------------------------------+
|                  确认操作                          |
|                                                  |
|  AI 置信度较低（58%），是否确认该风险项？            |
|                                                  |
|  风险 #003 - 争议解决                              |
|  "因本合同引起的争议，双方应协商解决..."              |
|                                                  |
|  +-----------------+  +----------------------+    |
|  |    取消          |  |      确认            |    |
|  +-----------------+  +----------------------+    |
+--------------------------------------------------+
```

- 取消按钮：灰色描边
- 确认按钮：蓝色实心 `#1976D2`
- 对话框居中显示，带半透明遮罩（opacity 40%）

确认后行为与高置信度相同（Toast + 卡片弱化 + 状态更新）。

### 1.2 Edit（修改）

点击"修改"后，从页面右侧滑出 480px 宽的抽屉面板。

#### 1.2.1 触发与关闭

- 触发方式：点击卡片底部 `[ 修改 ]` 按钮
- 滑入动画：从右向左滑入 300ms ease-out
- 遮罩：页面剩余区域半透明（opacity 40%），点击遮罩关闭
- 关闭方式：
  - 点击遮罩
  - 点击抽屉右上角 `[X]` 按钮
  - 按 `Esc` 键
  - 提交修改后自动关闭

#### 1.2.2 抽屉面板布局

```
+----------------------------------------------------------+
|  修正风险 #001                                      [X]  |
+----------------------------------------------------------+
|                                                          |
|  风险等级调整                                              |
|  +----------------------------------------------------+  |
|  |  [o] 保持原等级 [HIGH] (红色)                         |  |
|  |  [ ] 降为中风险 [MEDIUM] (橙色)                       |  |
|  |  [ ] 降为低风险 [LOW] (黄色)                          |  |
|  +----------------------------------------------------+  |
|                                                          |
|  审查意见（预填 AI 原意见）                                 |
|  +----------------------------------------------------+  |
|  | 单方无限制解除权，违反公平原则，                       |  |
|  | 可能导致乙方权益受损。                                  |  |
|  |                                                     |  |
|  |                                                     |  |
|  +----------------------------------------------------+  |
|  可编辑，支持最多 500 字                                    |
|                                                          |
|  修改建议                                                 |
|  +----------------------------------------------------+  |
|  | 建议增加双方协商解除条款，或限定解除条件                 |  |
|  | 为严重违约情形。                                       |  |
|  |                                                     |  |
|  |                                                     |  |
|  +----------------------------------------------------+  |
|  可编辑，支持最多 500 字                                    |
|                                                          |
|  法律依据                                                 |
|  +----------------------------------------------------+  |  |
|  | 《中华人民共和国民法典》第五百六十三条：                  |  |
|  | 有下列情形之一的，当事人可以解除合同...                   |  |
|  |                                                     |  |
|  |                                                     |  |
|  +----------------------------------------------------+  |
|  可编辑，支持最多 500 字                                    |
|                                                          |
+----------------------------------------------------------+
|  [ 取消 ]                              [ 保存修改 ]        |
+----------------------------------------------------------+
```

#### 1.2.3 字段说明

| 字段 | 类型 | 默认值 | 必填 | 说明 |
|------|------|--------|------|------|
| 风险等级调整 | 单选按钮组 | 保持原等级 | 是 | 三个选项：保持原等级 / 降为中风险 / 降为低风险 |
| 审查意见 | 多行文本 | AI 原 `description` | 否 | 用户可修改 AI 的风险说明 |
| 修改建议 | 多行文本 | AI 原 `suggestion` | 否 | 用户可修改建议内容 |
| 法律依据 | 多行文本 | AI 原 `legal_basis` | 否 | 用户可补充或修正法律依据 |

- 预填逻辑：三个编辑器在抽屉打开时自动填入 AI 原始值
- 保存校验：至少有一个字段与原始值不同，否则 `[ 保存修改 ]` 按钮保持禁用
- 保存后行为：
  - 调用 `PUT /api/v1/tasks/{task_id}/risks/{risk_id}/review`，`action: "modify"`
  - `modified_content` 包含变更的字段
  - 如果风险等级被调整，在 `modified_content.level` 中传递
  - 抽屉自动关闭
  - 卡片更新为"已修正"状态标签
  - Toast：`已修正` + 显示变更标记

#### 1.2.4 完成态

```
+------------------------------------------------------------------+
|  [HIGH] 风险 #001 - 违约责任                      [已修正] [展开v]|
|  置信度: 92%  操作人: user-001  2026-04-10 07:00                   |
|  透明度: 60% | 默认折叠                                           |
|                                                                  |
|  [展开后显示变更对比]                                              |
|  +--------------------------------------------------------------+|
|  | 审查意见:                                                    ||
|  | - 原: 单方无限制解除权...                                      ||
|  | + 新: 单方解除权未限定条件...                                   ||
|  |                                                              ||
|  | 风险等级: [HIGH] -> [MEDIUM]                                  ||
|  +--------------------------------------------------------------+|
+------------------------------------------------------------------+
```

- 状态标签 `已修正`：橙色背景 `#FFF3E0`，橙色文字 `#E65100`
- 展开后显示 diff 风格的变更对比（`-` 删除行红色背景，`+` 新增行绿色背景）

### 1.3 Reject（驳回）

点击"驳回"后，在卡片底部内联展开驳回面板（不弹抽屉）。

#### 1.3.1 内联驳回面板

```
+------------------------------------------------------------------+
|  [HIGH] 风险 #001 - 违约责任                                       |
|  置信度: 92%                                                      |
|  ...（风险项卡片内容）...                                           |
|  +--------------------------------------------------------------+|
|  |  [ 确认 ]   [ 修改 ]   [ 驳回(激活) ]                           ||
|  +--------------------------------------------------------------+|
|  +--------------------------------------------------------------+|
|  |  驳回原因（必选）                                               ||
|  |  +--------------------------------------------------------+  ||
|  |  | ( ) 误报 - AI 识别错误，该条款无风险                        |  ||
|  |  | ( ) 不适用 - 该条款对本合同类型不适用                       |  ||
|  |  | ( ) 已修正 - 合同已更新，该风险已消除                       |  ||
|  |  | ( ) 其他 - 其他原因                                       |  ||
|  |  +--------------------------------------------------------+  ||
|  |                                                              ||
|  |  补充说明（选填）                                               ||
|  |  +--------------------------------------------------------+  ||
|  |  | 可选填驳回理由，如"该条款为标准模板，已在法务库备案"          |  ||
|  |  |                                                        |  ||
|  |  +--------------------------------------------------------+  ||
|  |  最多 200 字                                                   ||
|  |                                                              ||
|  |                    [ 取消 ]  [ 确认驳回 ]                      ||
|  +--------------------------------------------------------------+|
+------------------------------------------------------------------+
```

#### 1.3.2 交互规则

- 展开方式：点击 `[ 驳回 ]` 后，卡片底部向下滑出 300ms
- 预设原因：单选按钮，必须选择一项才能激活 `[ 确认驳回 ]` 按钮
- 补充说明：可选输入，最多 200 字
- 取消：点击后收起驳回面板，恢复为初始状态
- 确认驳回：
  - 调用 `PUT /api/v1/tasks/{task_id}/risks/{risk_id}/review`，`action: "reject"`
  - `comment` 字段 = 选中的预设原因 + 补充说明（如有），格式：`误报：该条款为标准模板`

#### 1.3.3 完成态

```
+------------------------------------------------------------------+
|  [HIGH] 风险 #001 - 违约责任                    [已驳回] [展开v]  |
|  置信度: 92%  操作人: user-001  2026-04-10 07:00                   |
|  透明度: 60% | 默认折叠                                           |
|  驳回原因: 误报                                                    |
+------------------------------------------------------------------+
```

- 状态标签 `已驳回（误报）`：红色背景 `#FFEBEE`，红色文字 `#C62828`
- 括号中显示预设原因，如果是"其他"则显示 `已驳回`
- Toast：`已驳回（误报）`（红色背景，1.5s 自动消失）

## 2. 批量操作 UI

### 2.1 列表选择

风险项列表的每一项左侧增加 checkbox：

**默认态（未选中）**：

```
+------------------------------------------------------------------+
| [ ]  [HIGH] 风险 #001 - 违约责任                    置信度: 92%    |
|     单方无限制解除权，违反公平原则...                               |
+------------------------------------------------------------------+
| [ ]  [MEDIUM] 风险 #002 - 知识产权                 置信度: 65%    |
|     未明确约定知识产权归属...                                       |
+------------------------------------------------------------------+
| [ ]  [LOW] 风险 #003 - 争议解决                   置信度: 58%    |
|     争议解决方式约定不明确...                                       |
+------------------------------------------------------------------+
```

- 仅 `human_review_status == "pending"` 的项显示 checkbox
- 已处理项不显示 checkbox
- checkbox 区域宽度：32px

**选中态**：

```
+------------------------------------------------------------------+
| [x]  [HIGH] 风险 #001 - 违约责任                    置信度: 92%    |
|     单方无限制解除权，违反公平原则...                               |
+------------------------------------------------------------------+
| [ ]  [MEDIUM] 风险 #002 - 知识产权                 置信度: 65%    |
|     未明确约定知识产权归属...                                       |
+------------------------------------------------------------------+
| [x]  [LOW] 风险 #003 - 争议解决                   置信度: 58%    |
|     争议解决方式约定不明确...                                       |
+------------------------------------------------------------------+
```

- 选中项：卡片左侧出现 3px 宽蓝色竖线 `#1976D2`
- 全选 checkbox：列表顶部显示，点击选中/取消所有待处理项

### 2.2 底部浮动工具栏

当选中 >= 1 项时，从页面底部滑出浮动工具栏：

```
+----------------------------------------------------------+
|  [ ] 全选    已选择 2 项                                    |
|                                                          |
|     [ 批量确认 ]                    [ 批量驳回 ]            |
+----------------------------------------------------------+
```

- 工具栏固定于视口底部，z-index 高于内容区域
- 滑入动画：从底部向上 300ms ease-out
- 关闭动画：当选中数回到 0 时向下滑出
- 按钮：
  - `[ 批量确认 ]`：蓝色描边 `#1976D2`
  - `[ 批量驳回 ]`：红色描边 `#C62828`

### 2.3 批量确认

点击 `[ 批量确认 ]` 后：

1. 调用 `POST /api/v1/tasks/{task_id}/reviews/batch`，`reviews` 数组中所有项 `action: "approve"`
2. 成功后：
   - 所有选中项更新为"已确认"状态
   - 工具栏关闭
   - checkbox 清空
   - Toast：`已确认 X 项`

### 2.4 批量驳回弹窗

点击 `[ 批量驳回 ]` 弹出驳回对话框（不同于单条的内联面板，批量操作使用居中对话框）：

```
+----------------------------------------------------------+
|                    批量驳回                                |
|                                                          |
|  已选择 3 项                                               |
|                                                          |
|  驳回原因（必选）                                           |
|  +----------------------------------------------------+  |
|  | ( ) 误报 - AI 识别错误，这些条款无风险                  |  |
|  | ( ) 不适用 - 这些条款对本合同类型不适用                 |  |
|  | ( ) 已修正 - 合同已更新，这些风险已消除                  |  |
|  | ( ) 其他 - 其他原因                                  |  |
|  +----------------------------------------------------+  |
|                                                          |
|  补充说明（选填）                                           |
|  +----------------------------------------------------+  |
|  |                                                    |  |
|  |                                                    |  |
|  +----------------------------------------------------+  |
|  最多 200 字                                              |
|                                                          |
|  +------------------+  +-----------------------------+   |
|  |      取消         |  |        确认驳回              |   |
|  +------------------+  +-----------------------------+   |
+----------------------------------------------------------+
```

- 选中原因后 `[ 确认驳回 ]` 按钮才激活
- 提交逻辑与批量确认类似，`action: "reject"`，所有项共用同一 `comment`
- 成功后 Toast：`已驳回 X 项（误报）`

## 3. 操作反馈 UI

### 3.1 已处理项视觉规范

| 属性 | 值 | 说明 |
|------|-----|------|
| 透明度 | `opacity: 0.6` | 视觉上弱化已处理项 |
| 默认状态 | 折叠 | 仅显示摘要行，内容隐藏 |
| 展开方式 | 点击 `[展开]` | 可查看完整内容和变更记录 |
| 操作按钮 | 隐藏 | `[ 确认 ]` `[ 修改 ]` `[ 驳回 ]` 不显示 |

摘要行展示内容：

```
[状态标签]  风险编号  风险标题  置信度  操作人  操作时间
```

### 3.2 Toast 提示规范

| 操作 | Toast 文案 | 背景色 | 图标 | 持续时间 |
|------|-----------|--------|------|----------|
| 单条确认 | `已确认` | `#E8F5E9` 绿 | 对勾 | 1.5s |
| 单条修改 | `已修正` + 变更标记（如 `风险等级: HIGH->MEDIUM`） | `#FFF3E0` 橙 | 铅笔 | 3s |
| 单条驳回 | `已驳回（误报）` | `#FFEBEE` 红 | 叉号 | 1.5s |

| 批量驳回 | `已驳回 3 项（误报）` | `#FFEBEE` 红 | 叉号 | 2s |
| 审核会话超时 | `审核会话已超时，请重新发起` | `#FFEBEE` 红 | 警告 | 5s |

- 位置：页面右上角
- 出现动画：从右侧滑入 200ms
- 消失动画：向右滑出 200ms
- 同时最多显示 2 条 Toast，超出排队

### 3.3 状态标签

| 状态 | 文本 | 背景色 | 文字色 | 边框 |
|------|------|--------|--------|------|

| 已驳回 | `已驳回` | `#FFEBEE` 红 | `#C62828` | 无 |
| 已驳回（误报） | `已驳回（误报）` | `#FFEBEE` 红 | `#C62828` | 无 |
| 已驳回（不适用） | `已驳回（不适用）` | `#FFEBEE` 红 | `#C62828` | 无 |
| 已驳回（已修正） | `已驳回（已修正）` | `#FFEBEE` 红 | `#C62828` | 无 |

- 尺寸：小号标签，`padding: 2px 8px`，`border-radius: 4px`，`font-size: 12px`
- 更新动画：状态切换时标签有 300ms 的颜色渐变过渡

## 4. 审核会话管理 UI

### 4.1 会话状态栏

位于风险项列表顶部：

```
+------------------------------------------------------------------+
|  审核会话 #1 (第1轮)          剩余待处理: 5 高风险 | 8 中风险 | 12 低风险 |
|  状态: [审核中] (绿色)         超时: 23:45:12                     |
|  进度: ████████░░░░░░░░░░░░  25/25 已完成                          |
+------------------------------------------------------------------+
```

| 元素 | 数据来源 | 更新方式 |
|------|----------|----------|
| 审核轮次 | `ReviewSession.session_number` | 页面加载时获取 |
| 剩余待处理数 | API 返回 `remaining_pending` | 每次操作后实时更新 |
| 超时倒计时 | `ReviewSession.timeout_at` | 前端 `setInterval` 每秒更新 |
| 进度条 | `decisions_count / total_risks` | 每次操作后重新计算 |

### 4.2 超时提示

| 剩余时间 | 行为 | 视觉 |
|----------|------|------|
| > 1 小时 | 正常显示倒计时 | 绿色文字 |
| 30 分钟 ~ 1 小时 | 倒计时变橙色 | 橙色文字 `#E65100` |
| < 30 分钟 | 出现警告条 | 橙色背景警告条 `审核会话将在 30 分钟内超时` |
| < 5 分钟 | 出现严重警告 + 弹窗提醒 | 红色背景 + 每 60s 弹一次确认弹窗 |
| 已超时 | 禁用所有操作按钮 | 会话栏变灰 + Toast `审核会话已超时` |

超时警告条（< 30 分钟时内嵌于会话状态栏下方）：

```
+------------------------------------------------------------------+
|  [警告图标] 审核会话将在 23:45 后超时，请尽快完成审核                |
+------------------------------------------------------------------+
```

超时弹窗（< 5 分钟时）：

```
+----------------------------------------------------------+
|  [!] 审核会话即将超时                                     |
|                                                          |
|  当前会话将在 3 分钟后超时。                              |
|  超时后未处理的风险项将需要重新发起审核。                    |
|                                                          |
|  剩余待处理: 2 高风险项                                    |
|                                                          |
|                    [ 继续审核 ]  [ 提交并退出 ]             |
+----------------------------------------------------------+
```

### 4.3 剩余待处理高风险计数

- 显示位置：审核会话状态栏 + 页面标题徽章
- 数据源：单条审核 API 返回 `remaining_pending` 字段 + 批量审核 API 返回 `remaining_pending`
- 前端也可本地维护计数：每次操作成功后 `remaining_pending -= 成功条数`
- `remaining_pending == 0` 时，"生成报告"按钮从禁用变为可用

## 7. 前端状态管理建议

### 7.1 全局 Store 结构

```
ReviewState {
  // 审核会话
  session: {
    sessionNumber: number        // 当前轮次
    totalRisks: number           // 总风险数
    decisionsCount: number       // 已决策数
    status: 'active' | 'completed' | 'timeout'
    timeoutAt: string | null     // ISO 8601
  }

  // 风险项列表
  items: RiskItem[]             // 原始数据

  // 批量选择
  selectedIds: Set<string>      // 选中的 risk_id 集合

  // 待处理计数
  remainingPending: number      // 剩余高风险待处理数

  // 本地操作队列（乐观更新）
  pendingOperations: Map<risk_id, {
    action: 'approve' | 'modify' | 'reject'
    status: 'pending' | 'success' | 'error'
  }>
}
```

### 7.2 选中列表维护

- 数据结构：`Set<string>`，key 为 `risk_id`
- 添加：checkbox 勾选时 `selectedIds.add(risk_id)`
- 移除：checkbox 取消时 `selectedIds.delete(risk_id)`
- 全选：将所有 `human_review_status == 'pending'` 的项加入 Set
- 取消全选：清空 Set
- 批量操作后：清空 Set

### 7.3 待处理计数更新

- 初始值：页面加载时从 `GET /api/v1/tasks/{task_id}/result` 获取高风险项数
- 每次操作后：优先使用 API 返回的 `remaining_pending` 字段
- 降级方案：API 失败时本地计算 `items.filter(i => i.level === 'high' && i.human_review_status === 'pending').length`

### 7.4 乐观更新策略

| 操作 | 乐观行为 | 回滚条件 |
|------|----------|----------|
| 确认 | 立即将卡片标记为已确认 | API 返回错误，恢复为 pending |
| 驳回 | 立即标记为已驳回 | API 返回错误，恢复为 pending |
| 修改 | 关闭抽屉，标记为已修正 | API 返回错误，重新打开抽屉 |
| 批量操作 | 立即更新所有选中项状态 | API 返回错误，批量恢复选中状态 |

- 乐观更新期间，操作按钮禁用，防止重复提交
- API 返回错误时，Toast 显示错误信息，同时恢复 UI 状态

### 7.5 超时倒计时

- 数据源：`ReviewSession.timeout_at`
- 前端实现：`setInterval` 每秒计算 `timeoutAt - now`
- 组件卸载时 `clearInterval` 清理
- 倒计时值存入 Store，各组件通过 selector 读取

### 7.6 操作日志

- 加载时机：用户点击 `[ 操作日志 ]` 按钮时
- 缓存：加载后缓存在 Store 中，再次打开不需要重新请求
- 实时更新：每次操作成功后，前端将操作追加到日志列表（同时调用 API 记录）
- 分页：首次加载 20 条，滚动到底部加载更多
