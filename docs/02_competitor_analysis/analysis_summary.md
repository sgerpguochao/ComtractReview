# 竞品分析总结

> 本阶段由 Agent Team 协作完成：
> - **workflow-analyst**：审核流程拆解（文档上传 → 解析 → 自动审核 → 人工审核 → 报告生成）
> - **presentation-analyst**：审核结果呈现（风险项列表、原文定位、解释性数据展示）
> - **Lead**：汇总分析

---

## 核心结论

### 1. 审核流程设计

**最优流程路径**：
```
上传合同 → OCR预处理 → 文档解析 → 条款提取 → 风险识别
    ↓
Agent 初审 → 生成风险列表 → 高风险项触发人工审核
    ↓
人工确认/修正 → 合规检查 → 模板比对 → 生成审查报告
```

**关键发现**：
- 文档解析质量是审核质量的基石，条款边界识别必须做好
- 人工审核不可省略，但可优化为"仅高风险项审核"提升效率
- 混合技术路线（规则引擎 + LLM）比单一方案更可靠

**必须环节**：文档解析、风险识别、人工审核、报告生成
**可简化环节**：模板比对（初期做简单差异对比）、合规检查（先覆盖主要法规）、批量上传（二期功能）

### 2. 结果呈现设计

**推荐的信息架构**：
- 首页总览（风险评分 + 统计）→ 详细审查（风险列表 + 逐条审核）→ 审查报告（执行摘要 + 详情清单）

**关键设计原则**：
| 原则 | 说明 |
|------|------|
| 最少点击 | 2 次点击内完成一个风险项处理 |
| 渐进式披露 | 默认摘要，按需展开详情 |
| 透明置信度 | 明确传达 AI 的不确定性 |
| 可追溯性 | 记录所有人工修正，为 AI 优化提供数据 |

**原文定位推荐方案**：左右分栏 + 高亮（审核体验最佳）+ 内联批注（修改场景）

## 竞品对比速查表

### 流程对比
| 流程环节 | Kira Systems | Luminance | Ironclad | LegalSifter |
|----------|-------------|-----------|----------|-------------|
| 文档上传 | 单文件+批量 | 单文件+批量 | API集成+UI | 单文件为主 |
| 解析处理 | NLP+ML | 专有ML模型 | 结构化解析 | NLP+规则 |
| 自动审核 | 预训练模型 | 自学习模型 | 规则引擎 | 专家知识库 |
| 人工审核 | 高风险项审核 | 全程可审核 | 按需审核 | 逐条确认 |
| 报告生成 | PDF+在线 | PDF+仪表板 | 结构化数据 | PDF+摘要 |

| 呈现维度 | Kira Systems | Luminance | Ironclad | LegalSifter |
|----------|-------------|-----------|----------|-------------|

| 置信度展示 | 无 | 有 | 有 | 有风险等级 |

## 对 ContractReview 的设计启示

1. **流程层面**：采用"Agent 初审 + 高风险人工审核"模式，平衡效率与准确性
2. **呈现层面**：首页总览 + 逐条详查的两级信息架构
3. **交互层面**：左右分栏原文对照 + 内联批注的混合模式
4. **技术层面**：规则引擎（高准确条款）+ LLM（语义理解条款）的混合审核
