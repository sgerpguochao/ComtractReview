# 合同审核流程拆解分析

## 1. 审核流程全景拆解

### 1.1 文档上传环节

#### 支持的文件格式
| 格式类型 | 支持情况 | 说明 |
|----------|----------|------|
| Word (.docx) | 主流竞品均支持 | 结构化数据最完整 |
| PDF（文本型） | 主流竞品均支持 | 需额外解析层级结构 |
| PDF（扫描件/图片） | 部分支持（需 OCR） | OCR 质量影响后续分析 |
| 纯文本 (.txt) | 少数支持 | 丢失格式和结构信息 |
| HTML | 少数支持 | 适用于在线合同 |

#### 上传方式
- **单文件上传**：基础能力，所有竞品均支持
- **批量上传**：Kira Systems 和 Luminance 支持批量上传用于尽职调查场景（数百份合同同时处理）
- **API 集成上传**：Ironclad 支持与 ERP/CRM 系统对接，自动拉取待审合同

#### 上传预处理
- OCR 识别（扫描件）
- 格式转换与归一化
- 重复文件检测
- 病毒扫描

### 1.2 解析处理环节

#### 文档结构解析
合同文档解析是审核质量的基石，各竞品在以下维度竞争：

| 解析能力 | Kira | Luminance | Ironclad |
|----------|------|-----------|----------|
| 标题层级识别 | 高 | 高 | 中 |
| 表格内容提取 | 中 | 高 | 低 |
| 附件/附录识别 | 中 | 中 | 低 |
| 手写批注识别 | 低 | 中 | 不支持 |
| 印章/签名区域识别 | 不支持 | 低 | 不支持 |

#### 条款边界识别
- **基于规则**：使用正则表达式和关键词定位条款起止（如"第X条"、"Article X"）
- **基于 LLM**：利用语义理解识别无明确编号的条款边界
- **混合方案**：规则定位 + LLM 校验（推荐方案）

#### 文本清洗
- 去除页眉页脚、水印文字
- 合并跨页断裂的段落
- 处理特殊字符和编码问题

### 1.3 Agent 自动审核环节

#### 条款自动提取
从合同文本中自动识别并提取关键条款要素：
- **价格/金额条款**：合同总价、付款节点、币种
- **时间条款**：生效日期、履行期限、续约条件
- **责任条款**：违约责任、赔偿上限、免责范围
- **争议解决**：管辖法院、仲裁机构、适用法律
- **保密条款**：保密范围、保密期限、例外情形

#### 风险条款识别
两种技术路线：
- **规则引擎**：预设风险关键词和模式匹配（如"单方解除权"、"不可撤销"），准确率高但覆盖有限
- **LLM 判断**：基于语义理解识别隐含风险，覆盖广但误报率高

#### 合规性检查
- 对照法律法规库（如《民法典》《劳动合同法》）
- 检查强制性条款是否缺失
- 验证条款是否违反强制性规定

#### 与标准模板比对
- 将待审合同与企业标准模板进行逐条对比
- 标记新增、删除、修改的条款
- 生成差异报告

### 1.4 人工审核环节

#### 介入时机
| 介入模式 | 适用场景 | 代表产品 |
|----------|----------|----------|
| 全程审核（每条款都确认） | 高风险合同 | LegalSifter |
| 仅高风险项审核 | 日常合同 | Kira Systems |
| 按需触发审核 | 标准合同 | Ironclad |

#### 审核界面设计
- **左右分栏对比**：左侧原文高亮风险条款，右侧显示审查意见（Kira、Luminance）
- **列表式**：风险项列表，点击展开详情（Ironclad CLM 模式）
- **批注模式**：在原文上直接添加审查批注（类 Word 审阅模式）

#### 审核人员操作
- **确认**：认同 AI 判断，标记为已处理
- **修正**：调整风险等级、修改审查意见
- **驳回**：认为误报，标记为"无风险"
- **补充**：添加 AI 未识别到的额外风险

### 1.5 报告生成环节

#### 报告格式
- **PDF 报告**：正式审查报告，适合归档和对外提交
- **在线预览**：交互式报告，支持在线查看和批注
- **结构化数据**：JSON/XML 格式，适合系统集成

#### 报告内容组成
1. **执行摘要**：合同整体风险评分、高风险项数量、审查结论
2. **风险摘要**：按风险等级排列的条款清单
3. **逐条分析**：每个风险条款的原文、风险说明、修改建议、法律依据
4. **合规检查清单**：各项合规检查的通过/未通过状态
5. **修改建议汇总**：所有建议修改的条款及建议文本

## 2. 各竞品流程对比

| 流程环节 | Kira Systems | Luminance | Ironclad | LegalSifter |
|----------|-------------|-----------|----------|-------------|
| 文档上传 | 单文件+批量 | 单文件+批量 | API集成+UI | 单文件为主 |
| 解析处理 | NLP+ML | 专有ML模型 | 结构化解析 | NLP+规则 |
| 自动审核 | 预训练模型 | 自学习模型 | 规则引擎 | 专家知识库 |
| 人工审核 | 高风险项审核 | 全程可审核 | 按需审核 | 逐条确认 |
| 报告生成 | PDF+在线 | PDF+仪表板 | 结构化数据 | PDF+摘要 |

## 3. 流程设计建议

### 3.1 最优流程路径
```
上传合同 → OCR预处理（如需要）→ 文档解析 → 条款提取 → 风险识别
    ↓
Agent 初审 → 生成风险列表 → 高风险项触发人工审核
    ↓
人工确认/修正 → 合规检查 → 模板比对 → 生成审查报告
```

### 3.2 必须包含的环节
- 文档解析（条款边界识别是基础）
- 风险条款识别（核心价值）
- 人工审核（风险兜底）
- 报告生成（交付物）

### 3.3 可简化的环节
- 模板比对：初期可只做简单差异对比，后期再做深度语义比对
- 合规检查：先覆盖主要法规（民法典、劳动法），后续逐步扩展
- 批量上传：初期只支持单文件上传，批量上传作为二期功能
